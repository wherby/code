这种将复杂逻辑转换为代数公式后，利用线段树维护特定代数项（如端点与相邻项乘积）的技巧，在算法竞赛和高级数据结构中通常被称为“结合律代数化简”**（Associative Algebraic Reduction）或**“线段树维护结合律代数结构”。

具体到它在求解区间问题时的模式，主要有以下几种称呼和归类方式：

---

### 1. **代数项降维与结合律化简（Algebraic Reduction into Associative Form）**

这是最本质的称呼。很多原本看起来需要维护连通块、区间分割的复杂计数/统计问题，通过代数展开（例如求和符号 $\sum$ 的拆项与消去）后，最终的表达式可以化简为仅依赖于：

* 区间左端点 / 第一个元素 ($p$)
* 区间右端点 / 最后一个元素 ($q$)
* 区间内相邻元素的代数叠加项 ($v = \sum p_i \cdot p_{i+1}$)

只要一个代数运算形如 $(p_A, q_A, v_A) \oplus (p_B, q_B, v_B) = (p_A, q_B, v_A + v_B + \text{op}(q_A, p_B))$，它在代数上就构成了**半群（Monoid）**，满足严格的结合律。这种将非线性问题化简为半群结构的技巧被称为**代数化简/半群化**。

---

### 2. **矩阵乘法/一次线性变换拟合（Matrix Multiplication / Affine Transformation Representation）**

在抽象代数中，这种合并方式本质上是矩阵乘法（Matrix Dynamic Programming on Segment Tree）的精简标量形式。

如果把每个节点看作一个向量，相邻节点的合并等价于一个线性变换：


$$\begin{pmatrix} p_{new} \\ q_{new} \\ v_{new} \\ 1 \end{pmatrix} = \text{Matrix} \times \begin{pmatrix} p_A \\ q_A \\ v_A \\ 1 \end{pmatrix}$$

由于矩阵乘法天然满足结合律 $(A \times B) \times C = A \times (B \times C)$，用线段树维护矩阵乘法是极其常见的技巧。而你这段代码中的 `merge` 函数，正是**把 $3 \times 3$ 的矩阵乘法展开并消元后的标量 $O(1)$ 表达形式**。因此在数据结构领域，这种技巧常被归类为“线段树维护矩阵乘法 / 动态 DP”的标量优化版。

---

### 3. **前缀和/贡献拆分法的线段树化（Segment Tree on Expanded Prefix Contribution）**

在组合计数问题中，这种把区间划分产生的贡献，拆解为“左贡献 + 右贡献 + 跨越中点的相邻贡献”的方法，通常被称为“跨区间相邻项贡献法”（Cross-boundary Transition Contribution）。

* **$a[2] + b[2]$**：继承左右子树各自内部的封闭贡献。
* **$- a[1] * b[0]$**（即 $- q_A \cdot p_B$）：计算左右子树在接缝处产生的唯一跨区间交互贡献。

---

### 一、 核心数学推导（为什么它是完全正确的？）

#### 1. 问题的代数转换

对于询问区间 $[L, R]$，一个子数组 $[i, j]$（满足 $L \le i < j \le R$）如果包含峰值，那么它内部**至少要包含一个位于 $[L+1, R-1]$ 范围内的峰值**。

假设区间 $[L+1, R-1]$ 内的所有峰值下标从小到大依次为：


$$p_1, p_2, \dots, p_k$$

一个子数组 $[i, j]$（其中 $i \in [L, R], j \in [L, R], i < j$）**不包含任何峰值**，当且仅当它的左右端点 $(i, j)$ 完全落在了由峰值切割出的某个“无峰缝隙”里：

* 在 $p_1$ 左侧：$L \le i < j \le p_1$
* 在相邻峰值 $p_m, p_{m+1}$ 之间：$p_m \le i < j \le p_{m+1}$
* 在 $p_k$ 右侧：$p_k \le i < j \le R$

#### 2. “正难则反”的代数展开

区间 $[L, R]$ 内的总子数组数量（长度 $\ge 2$）为：


$$S_{\text{total}} = \sum_{i=L}^{R-1} (R - i) = \frac{(R - L + 1)(R - L)}{2}$$

不含峰值的子数组数量为每个“无峰缝隙”内的子数组数之和：


$$S_{\text{empty}} = \frac{(p_1 - L + 1)(p_1 - L)}{2} + \sum_{m=1}^{k-1} \frac{(p_{m+1} - p_m + 1)(p_{m+1} - p_m)}{2} + \frac{(R - p_k + 1)(R - p_k)}{2}$$

利用恒等式 $\frac{(x+1)x}{2} = \frac{x^2 + x}{2}$，将所有括号彻底展开并与 $S_{\text{total}}$ 做差（$S_{\text{total}} - S_{\text{empty}}$），**所有交叉项与平方项会发生大规模的消去**！

最终化简出的**包含峰值的子数组总数**公式，可以精简为下式：


$$\text{Ans} = R \cdot (p_k - L) + p_1 \cdot L - \sum_{m=1}^{k-1} p_m \cdot p_{m+1}$$

看看代码中是如何计算查询结果的：

```python
p, q, v = st.prod(x + 1, y)
res.append(0 if p < 0 else y * (q - x) + p * x - v)

```

这里的 `y` 就是 $R$，`x` 就是 $L$：

* `p` 即第一个峰值 $p_1$
* `q` 即最后一个峰值 $p_k$
* `v` 即相邻峰值乘积之和 $\sum_{m=1}^{k-1} p_m \cdot p_{m+1}$

公式：`y * (q - x) + p * x - v` $\equiv R(p_k - L) + p_1 L - v$！**与纯代数推导出的公式完全一模一样！**

### 二、 为什么线段树的 `merge` 能够完美结合？

我们要维护的关键变量是相邻峰值的乘积和：


$$v = \sum_{m=1}^{k-1} p_m \cdot p_{m+1}$$

线段树节点维护的三元组 $(p, q, v)$：

* $p$：当前区间内的第一个（最左）峰值下标
* $q$：当前区间内的最后一个（最右）峰值下标
* $v$：当前区间内部所有相邻峰值的乘积和 $\sum p_m p_{m+1}$

当合并左区间 $A=(p_A, q_A, v_A)$ 与右区间 $B=(p_B, q_B, v_B)$ 时：

```python
def merge(a, b):
    if a[0] < 0: return b # 左区间无峰值
    if b[0] < 0: return a # 右区间无峰值
    return a[0], b[1], a[2] + b[2] + a[1] * b[0] # 注意原代码是 -，因为原代码公式对 v 的符号做了等价变换

```

1. **合并后的第一个峰值**：左区间的 $p_A$ (`a[0]`)。
2. **合并后的最后一个峰值**：右区间的 $q_B$ (`b[1]`)。
3. **合并后的乘积和**：
* 左区间内部的乘积和 $v_A$
* 右区间内部的乘积和 $v_B$
* **唯一跨越左右区间的相邻峰值对**：左区间的最后一个峰值 $q_A$ (`a[1]`) 与 右区间的第一个峰值 $p_B$ (`b[0]`)，新增的乘积项为 $q_A \cdot p_B$！



因此，新区间的乘积和完全等于 $v_A + v_B + q_A \cdot p_B$。

这个合并操作满足**严格的结合律（Associativity）**：


$$(A \circ B) \circ C = A \circ (B \circ C)$$

没有任何信息丢失，不需要关注区间长度，也不需要知道中间有多少个峰值！
