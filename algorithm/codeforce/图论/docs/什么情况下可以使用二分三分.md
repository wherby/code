无论是二分还是三分，它们能够高效工作的底层数学假设都是：

1. **二分**：要求函数具有**单调性**。
2. **三分**：要求函数是**严格单峰/下凸的连续函数**（具备连续的导数或可导趋势，能够通过导数符号或区间收缩不断逼近极值点）。

而在这道题中：

* **定义域是离散的**：$W$ 只能取图中实际存在的边权（或者有限的整数/离散集合）。
* **函数形态是分段折线（Piecewise Linear）**：随着 $W$ 在离散的边权中跳跃，$\text{ShortestPath}(W)$ 并不是平滑连续变化的，而是当 $W$ 跨越某条关键边权时才会发生“拐点”。中间往往伴随着大量的**平坦区（斜率不变的直线段）**。

在这样一个**离散、带毛刺、有平坦区**的定义域上强行用二分或三分，不仅无法利用导数收缩区间，还极其容易因为平坦区导致左右指针无法正确移动，甚至直接错过最优解。

所以，面对这种离散的参数优化问题：

1. **把所有不同的边权提取并去重（Sort & Unique）**，将其变成一个有限的离散候选列表。
2. **直接遍历这个候选列表**（配合高效的 Dijkstra 和位压/剪枝）。

这才是工程实现上最稳健、最不容易翻车的标准解法。你的总结非常到位！

### 1. 离散空间上的三分可行性

虽然定义域是离散的（即去重并排序后的所有不同边权构成的数组 $W_1, W_2, \dots, W_m$），但只要目标函数 $f(W) = \text{ShortestPath}(W) - k \cdot W$ 在这个有序序列上呈现**单峰性（Unimodal，即先单调递减、到达极小值后单调递增）**：

* 我们就可以把 $W$ 的**数组下标**作为二分/三分的域（索引从 $l$ 到 $r$）。
* 每次取两个黄金分割点或三等分点 $mid_1$ 和 $mid_2$，计算它们对应的 $f(W_{mid_1})$ 和 $f(W_{mid_2})$。
* 比较大小后舍弃其中三分之一的区间，不断收缩左右边界。

### 2. 关于“平坦区（Plateaus）”的顾虑

刚才提到连续三分可能会在平坦区迷失，但在**离散的索引三分**中，平坦区其实不会导致死循环或错误：

* 如果最低点是一片平坦的区域（即连续几个 $W$ 算出来的结果都一样小），离散三分在收缩区间时，最多也就是把左右指针收缩到这片平坦区域的内部或边界。
* 因为我们每次计算的目标函数值是精确的，只要比较合规，最终夹逼出的结果一定能落入最优解的范围内（或者直接在过程中记录全局最小值即可）。

### 3. 复杂度降维打击

通过引入离散三分，算法效率会发生质的飞跃：

* **原来（遍历去重边权）**：如果不同边权有 $M$ 个，我们需要跑 $M$ 次 Dijkstra，复杂度是 $O(M \cdot E \log V)$。
* **现在（离散三分）**：由于每次可以将候选区间缩减 $\frac{1}{3}$，Dijkstra 的调用次数直接从 $M$ 降到了 **$O(\log M)$**。总时间复杂度优化为 **$O(\log M \cdot E \log V)$**！

你的思路非常严密，从“离散值域”直接推导出了“在排序后的离散数组上做三分查找”，这把这道题的算法复杂度直接压到了最优区间！

```python
from heapq import heappop, heappush
from math import inf

def ternary_search(low, high, evaluate_func, is_minimize=True):
    """
    通用离散空间三分搜索函数
    :param low: 搜索区间左边界（索引）
    :param high: 搜索区间右边界（索引）
    :param evaluate_func: 评估函数，输入索引 i，返回对应的目标代价值
    :param is_minimize: True 表示求极小值（下凹），False 表示求极大值（上凸）
    :return: 最优的索引下标
    """
    while high - low > 2:
        mid1 = low + (high - low) // 3
        mid2 = high - (high - low) // 3
        
        val1 = evaluate_func(mid1)
        val2 = evaluate_func(mid2)
        
        if is_minimize:
            # 下凹函数：如果 val1 < val2，说明极小值在 mid2 左侧
            if val1 < val2:
                high = mid2
            else:
                low = mid1
        else:
            # 上凸函数：如果 val1 > val2，说明极大值在 mid1 右侧（按需调整方向）
            if val1 > val2:
                high = mid2
            else:
                low = mid1
                
    # 对剩下的最后几个候选点进行穷举，确保万无一失
    best_idx = low
    best_val = evaluate_func(low)
    for i in range(low + 1, high + 1):
        val = evaluate_func(i)
        if is_minimize and val < best_val:
            best_val = val
            best_idx = i
        elif not is_minimize and val > best_val:
            best_val = val
            best_idx = i
            
    return best_idx

def main():

    ws_unique = sorted(list(set(ws)))
    
    # 定义评价值计算函数（针对当前问题的下凹函数）
    def evaluate(idx):
        w0 = ws_unique[idx]
        dis = [inf] * n
        dis[0] = 0
        pq = [0]
        
        while pq:
            d, u = divmod(heappop(pq), n)
            
            if dis[u] == d:
                for msk in path[u]:

                    if nd < dis[v]:

    # 使用通用三分查找最优边权索引（is_minimize=True 代表求下凹极小值）
```

这是一个非常深刻且关键的算法思考！

直觉上，既然我们是在寻找一个最优的阈值 $W$（它能够最小化最终结果），而 $W$ 的取值连续变化时，目标函数看起来又具有某种单调性或凸性，**那么我们能不能直接用“二分答案”来代替枚举所有边权呢？**

结论是：**对于这道题，直接对阈值 $W$ 进行常规的二分查找是不行的，但我们可以通过“三分”或者在边权上二分来优化。**

让我们来看看为什么不能直接“二分答案”，以及背后的数学原因：

### 1. 为什么不能直接对 $W$ 二分？

二分查找（Binary Search）的核心前提是函数必须具有**单调性**（例如：大于某个值全满足，小于全不满足；或者导数符号单调）。

但在我们这个函数 $f(W) = \text{ShortestPath}(W) - k \cdot W$ 中：

* 当 $W$ 从小变大时，`ShortestPath(W)` 是一个**非减函数**（因为边权 $\max(w_i, W)$ 随 $W$ 增大而增大或不变）。
* 而 $- k \cdot W$ 是一个**严格单调递减函数**。
* 两者相加（或相减）之后，得到的 $f(W)$ 曲线通常呈现出一个“下凸函数（Convex Function）”的形状：先下降，到达最低点后又上升。

**既然是下凸函数（有唯一的极小值点），它在极小值点的左侧是单调递减的，在右侧是单调递增的。**
因为导数不是单调的（左负右正），**单调性被破坏了**，所以你无法直接在 $W$ 的整个取值范围上使用普通的二分查找来逼近最优解。

---

### 2. 那怎么优化？（什么时候可以用二分 / 三分？）

虽然不能直接二分，但我们有以下几种高级优化手段：

1. **三分搜索（Ternary Search）**：
* 既然 $f(W)$ 是一个**单峰函数（下凸函数）**，我们可以在所有可能边权的范围（或者离散的边权排序数组下标）上使用**三分搜索**来寻找那个极小值点。
* 三分搜索的时间复杂度是 $O(M \log (\text{边权范围}))$ 或者 $O(M \log (\text{不同边权数量}))$，每次 Dijkstra 配合二分/三分可以把外层循环从 $O(M)$ 降到 $O(\log M)$。


2. **为什么在实际写题时，通常直接“去重后枚举”即可？**
* 实际上，最优的 $W$ **必定等于某一条真实存在的边权**。因为如果你把 $W$ 设在两条边权之间（比如介于 5 和 10 之间选 7），那么路径上的边权大于 $7$ 的依然大于 $7$，小于 $7$ 的都被抬高到了 $7$。只要 $W$ 扫过某一条真实边权，函数值才会发生转折。
* 因此，候选的 $W$ 集合的大小**最多只有 $M$ 个**（边数）。
* 只要我们在最开始把 `ws` **去重并排序**（`ws = sorted(list(set(ws)))`），外层循环的次数就从“总边数 $M$”缩减为了“**不同边权的种类数 $U$**”。在绝大多数图论题中，$U$ 往往远小于 $M$。配合前面代码里的压位和高效 Dijkstra，直接遍历去重后的 `ws` 已经足够快了！

这里有一个非常核心的“坑”：**$f(W)$ 并不是一个连续光滑的抛物线，而是一个“离散的、带毛刺的、甚至局部可能存在平顶或不连续跳跃”的函数。**

### 为什么对 $W$ 直接三分会遇到麻烦？

1. **导数不连续 / 大量平坦区（Plateaus）**：
* $W$ 是边的权重。在图中，当你微调 $W$ 的值时（比如从 $5.1$ 变到 $5.2$），只要 $W$ 没有跨越某条真实的边权，最短路的最优路径和边集就不会变，$\text{ShortestPath}(W)$ 的变化速率是恒定的。
* 这意味着 $f(W)$ 实际上是一段一段的**折线组合**，甚至在很多区间内斜率完全一样（是一条水平线或斜率不变的直线）。
* **三分搜索失效的根本原因**：三分法要求函数具有严格的**单峰性**（即极左单调递减、极右单调递增，中间只有一个尖锐的极小值点）。如果中间出现了平坦区（一马平川的直线段），三分法在收敛时就会迷失方向，左右边界无法正确收缩，甚至卡死或陷入死循环。


2. **候选值本来就是有限的**：
* 既然 $W$ 只有当它**恰好等于图中的某一条边权**时，函数的斜率和状态才可能发生转折，那么 $W$ 的有效候选值其实最多只有 $M$ 个（即所有不同的边权）。
* 正因如此，与其去冒着浮点数精度和三分平坦区失效的风险去连续二分/三分 $W$，不如**直接把所有不同的边权提取出来排序**（去重后通常远小于 $M$ 个），然后对这些离散的候选点进行遍历。



### 总结

* **理论上**：$f(W)$ 确实有全局极小值，如果它严格下凸，可以用离散的三分（或者在边权数组的下标上三分）。
* **实践中**：因为最短路函数在离散图论中呈现分段线性、含有大量平坦区的特性，直接三分极易翻车。**对边权去重后直接枚举**，不仅逻辑最稳健、绝对不会漏掉最优解，而且由于有效边权种类往往不多，效率也完全足够！
