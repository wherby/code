### 一、 为什么按位拆分“100 需要 9 个 11 和 1 个 1”？

按你的推导，针对数值 $100$：

* $100 = 9 \times 11 + 1$ （共需要 $9 + 1 = 10$ 张纸币）。

但实际上：

* $100 = 111 - 11$（如果在允许减法/找零的系统中，这很自然，但在**只能相加**的系统里不适用）。
* 用全 1 纸币**纯相加**凑 $100$：
* 最优解是：$8 \times 11 + 12 \times 1 = 88 + 12 = 100$（共 $8 + 12 = 20$ 张纸币）。
* 甚至可以直接看做：$9 \times 11 + 1 = 100$（共 $9 + 1 = 10$ 张纸币）。



你找出的 $9 \times 11 + 1 = 100$ 确实用了 10 张纸币。但**问题在于“多位组合时的位与位之间的借位与进位互动”**。

### 二、 反例验证：为什么单纯“逢 10 换 1”会失效？

假设我们要凑的数是 **$X = 110$**：

#### 1. 按照你描述的按位拆分贪心：

* **百位 100**：拆成 $9$ 个 $11$ 和 $1$ 个 $1$。
* **十位 10**：拆成 $10$ 个 $1$。
* **个位 0**：0 个。
* **汇总：**
* $11$ 纸币：$9$ 个。
* $1$ 纸币：$1 + 10 = 11$ 个。


* **按规则“多于 10 个 $1$ 变为 1 个 $11$ 和 1 个 $1$”：**
* $11$ 个 $1$ $\longrightarrow$ $1$ 个 $11$ + $1$ 个 $1$。
* 最终得到：$10$ 个 $11$ + $1$ 个 $1$ $\implies 10 \times 11 + 1 \times 1 = 111$（**凑成了 111，比 110 多了！**）。



这里发生了溢出，因为 $10$ 个 $1$ 变成 $1$ 个 $11$ 之后，数值增加了（$10 \to 11$ 增加了 1）。

#### 2. 正确的最小张数：

* $110 = 9 \times 11 + 11 \times 1 = 99 + 11 = 110$。
* 方案 A：$9$ 个 $11$ + $11$ 个 $1$（共 **20 张**）。
* 方案 B：$10$ 个 $11$（共 **10 张**，正好 $10 \times 11 = 110$）。

如果按你的拆分，百位的 $100$ 和十位的 $10$ 凑在一起时，**$9$ 个 $11$ + $1$ 个 $11$ 直接组合成了 $10$ 个 $11$**（只需 10 张）。

### 三、 根本原因：为什么“直接贪心”很棘手？

全 1 纸币进制系统（$R_1=1, R_2=11, R_3=111, \dots$）并不是标准的**非退化基数系统**：

1. **基底比例不固定：**
* $\frac{R_2}{R_1} = 11$
* $\frac{R_3}{R_2} = \frac{111}{11} = 10.0909\dots$
* $\frac{R_4}{R_3} = \frac{1111}{111} = 10.009\dots$
相邻纸币的比值不是固定的整数（不像十进制固定是 10，二进制固定是 2）。


2. **进制“进位”带尾巴：**
* 在二进制中：$2$ 个 $1$ 可以无缝换成 $1$ 个 $2$。
* 在十进制中：$10$ 个 $1$ 可以无缝换成 $1$ 个 $10$。
* 在本题中：$10$ 个 $1$ 换成 $1$ 个 $11$，**会凭空多出 $1$ 的数值**；如果要换成 $10$，又没有 $10$ 这张纸币。

### 总结

你的“按位拆分”直觉已经非常接近本质了（试图寻找 $10^c$ 和 $R_c$ 之间的固定线性组合）。但由于 $10 \times R_c + 1 = R_{c+1}$，**每次跨层级进位都会产生 $+1$ 的“残余量”**。

这恰恰就是为什么必须引入 $9X + k = \sum 10^{c_i}$ 的原因——**乘 9 的本质，就是把这种带“残余量 $+1$”的复杂进制，强制转化为完全没有残余量的标准十进制（$10^c$）进位问题**！

这里是整个算法**最精妙、最玄妙**的地方！

要理解为什么是 `s[i+1] == 1` 时减 `s[i+1]`，否则减 `s[i]`，我们需要回到代码在维护的核心等式：

$$\text{当前高精度数组 } s \text{ 代表的数值 } = 9X + k$$

同时，我们的目标是消去 $9X + k$ 中的数位，直到把所有高位都“清零”。

---

### 一、 核心机制：`ans += 1` 和 `s[0] += 1` 做了什么？

每次循环执行：

```python
ans += 1
s[0] += 1

```

这相当于 **$k$ 增加了 $1$**，同时高精度数组 $s$ 的最低位加了 $1$（并处理了进位）。

此时，你手中相当于获得了 **$1$ 单位的“抵消配额”**，你需要用这个配额去消掉 $9X + k$ 的高位数字（即抵消掉一个 $10^i$）。

---

### 二、 为什么会有 `s[i+1] == 1` 的情况？

请注意进位逻辑：
在执行 `s[0] += 1` 并处理完进位后，**进位可能会一路传递到 `s[i+1]**`！

假设我们当前正在处理第 `i` 位（`s[i]`）：

#### 情况 1：进位一路传到了第 `i + 1` 位，导致 `s[i+1] == 1`

* **发生了什么**：刚才的 `s[0] += 1` 触发了连锁进位，使得原本为 0 的第 `i+1` 位变成了 1（即产生了更高的数位 $10^{i+1}$）。
* **应该消谁**：因为出现了更高的数位 `s[i+1]`，最高位现在变成了 `i+1` 位！为了保持贪心消去最高位的原则，我们必须**优先消去这个刚进位产生的最高位 `s[i+1]**`。
* **操作**：`s[i+1] -= 1`（把它重新变回 0）。

#### 情况 2：进位没有影响到 `s[i+1]`（即 `s[i+1] == 0`）

* **发生了什么**：加 1 产生的进位没有到达 `i+1` 位。
* **应该消谁**：当前的最高有效位仍然是第 `i` 位（`s[i]`）。
* **操作**：`s[i] -= 1`（把当前正在消的第 `i` 位减去 1）。

### 三、 用一个具体例子看变化

假设当前数组 $s$ 到了某一时刻，正在处理 `i = 2`（百位），此时 `s` 的高位情况是：

* `s[3] = 0` (千位)
* `s[2] = 1` (百位)

我们要消掉 `s[2]` 的这个 $1$。

#### 1. 执行 `s[0] += 1`

假设低位刚好全是 $9$（比如 `s[0]=9, s[1]=9`），加 $1$ 后发生连续进位：

* `s[0]` 变成 0，`s[1]` 变成 0
* `s[2]` 原来是 1，进位后变成 $2$
* **甚至如果 `s[2]` 变成了 10，进位后 `s[3]` 变成了 1，`s[2]` 变成了 0！**

#### 2. 判断条件触发

如果连续进位直接让千位 `s[3]` 变成了 1：

* 这时候 `s[i+1]` 即 `s[3] == 1`。
* 此时最高位变成了 `s[3]`，我们直接 `s[3] -= 1` 把千位这颗刚冒出来的“钉子”拔掉。

如果进位只让 `s[2]` 变成了 2，`s[3]` 依然是 0：

* 此时 `s[i+1]` 即 `s[3] == 0`（不等于 1）。
* 执行 `else` 分支：`s[2] -= 1`，百位从 2 变回 1。

---

### 总结

`if s[i+1] == 1` **本质上是在处理“进位溢出防线”**：

由于我们每次都在做 `s[0] += 1`，这个 $+1$ 操作可能会在更高一位（`i+1` 位）产生一个新的 $1$。

* 如果产生了新高位（`s[i+1] == 1`），我们就用本次 $+1$ 的配额去**抵消这个新高位**；
* 如果没产生新高位，我们就用本次 $+1$ 的配额去**抵消当前目标位 `s[i]**`。

这种写法用极其精简的两行代码，完美盖掉了进位对最高位动态变化的影响！
