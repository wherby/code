### 一、 为什么一定是“前面是 0，后面是 1”时比值最小？

我们来做一次严谨的**单调性与极值证明**。

对于固定的路径，设选择的边权为 $w_1 \le w_2 \le \dots \le w_M$。
我们想**最小化**的目标函数是：

$$R(w_1, \dots, w_M) = \frac{\text{分子}}{\text{分母}} = \frac{\sum_{e \in \text{路径}} w_e}{\sum_{i=1}^k w_i}$$

#### 1. 固定其他变量，单独看某一个 $w_m$ 的影响

假设我们保持其他所有边的权值不动，只调整第 $m$ 条边的权值 $w_m$。
此时 $w_m$ 在分子中的系数为 $a \in \{0, 1\}$（取决于第 $m$ 条边是否在路径上），在分母中的系数为 $b \in \{0, 1\}$（取决于 $m \le k$ 是否成立）。

式子可以简化为关于 $w_m$ 的分式函数：

$$R(w_m) = \frac{A + a \cdot w_m}{B + b \cdot w_m} \quad (A, B > 0)$$

对 $w_m$ 求导数：

$$\frac{d R}{d w_m} = \frac{a B - b A}{(B + b \cdot w_m)^2}$$

注意到分母 $(B + b \cdot w_m)^2 > 0$ 恒成立，所以**导数的符号完全取决于分子 $(a B - b A)$ 的正负**！

#### 2. 导数符号意味着什么？

* 如果 $a B - b A > 0$：函数关于 $w_m$ **严格单调递增**。为了让 $R$ 最小，**$w_m$ 应该取到它的最小值边界**。
* 如果 $a B - b A < 0$：函数关于 $w_m$ **严格单调递减**。为了让 $R$ 最小，**$w_m$ 应该取到它的最大值边界**。

#### 3. 极值一定在“边界”上取得

因为整个函数关于每一个 $w_m$ 都是单调的（要么单调递增，要么单调递减），所以在多维可行域（由 $1 \le w_1 \le w_2 \le \dots \le w_M$ 构成的凸包）内，**最小值绝对不可能在内部取得，只能在可行域的“顶点（Extreme Points）”取得**！

而这个凸包的**顶点**对应的 $w$ 序列形态，正是**阶跃函数（Step Function）**：


$$w_1 = w_2 = \dots = w_t = 0, \quad w_{t+1} = \dots = w_M = 1$$

> **直观理解**：
> 要想让“分子 / 分母”最小：
> 1. 分子里的 $w_e$ 越小越好（能设成 $0$ 就设成 $0$）；
> 2. 分母里的 $w_i$ 越大越好（能设成 $1$ 就设成 $1$）。
> 
> 
> 但由于受限于 $w_1 \le w_2 \le \dots \le w_M$ 的单调递增约束，你不可能随机乱填，你**唯一能做的**就是选一个划界点 $t$，把前 $t$ 个压成最小值 $0$，把 $t$ 之后的拉满到最大值 $1$。

### 二、 这算不算是一个“动态图”的求解？

**从广义的算法思想上来看，这完全可以理解为一个“动态图”问题。**

但严格来说，它是一种“通过枚举一维参数，将动态图转化为 $M$ 次静态图”的降维打击策略：

#### 1. 为什么它像“动态图”？

* 随着断层点 $t$ 从 $0$ 一路增加到 $M-1$：
* 第 $t$ 条边的权值从 $1$ 变成了 $0$（相当于在图中“免费”了一条边）；
* 图的连通性和加权结构在发生**动态变化**（加权最短路在不断变短）；
* $t$ 变大，意味着免费公路变多，$1 \to N$ 的最短路 $D(t)$ **单调不增**。



#### 2. 为什么我们不用复杂的“动态图数据结构”？

如果要在边权动态修改（$1 \to 0$）的过程中实时维护最短路，在离线/可持久化图论中属于动态最短路（Dynamic Shortest Path）问题。

但在这道题里，因为 $M$ 的范围允许（或者通过 01-BFS 的高效性），我们不需要用复杂的动态树/可持久化数据结构，而是**直接把每个 $t$ 状态下的静态图独立出来，跑 $M$ 次 01-BFS**。

#### 总结它的全貌：

它的求解机制本质上是：

$$\text{连续空间的极值问题} \xrightarrow{\text{导数与顶点理论}} \text{离散的 } M \text{ 个 0-1 状态图} \xrightarrow{\text{01-BFS 求解}} \text{全局下确界}$$

这个从“连续无限的 $w$”降维到“$M$ 个 discrete 的 0-1 状态图”的过程，就是这道题最精妙的数学魅力！

**是的，你完全看透了！本质上就是一次“在理论保证下的完备暴力枚举”。**

很多人第一眼看到这道题，会以为需要设计某种极其复杂的连续优化算法或动态规划，但经过数学推导后，我们发现：

1. **理论证明**：证明了所有可能达到极值的边权配置，**只有 $M$ 种阶跃形态**（即在某个断点 $t$ 之前全为 0，之后全为 1）。
2. **算法实现**：既然全集被规约成了这 $M$ 种确定形态，我们直接用外层循环 `for i in range(m)` **把这 $M$ 个断点无死角地枚举一遍**，对每种形态跑一次 01-BFS，最后取最小值。

---

### 为什么这种“暴力”能行得通，而且是正确的？

* **它不是“盲目瞎猜的暴力”**：如果是普通的暴力，在连续实数空间 $w_1 \le w_2 \le \dots \le w_M$ 里有无穷多种取值组合，根本不可能枚举完。
* **它是“降维后的完备枚举”**：数学证明帮我们做了一次**搜索空间的降维**，把一个连续无穷维的极值问题，裁剪成了一个只包含 $M$ 个顶点的离散集合。

所以，这正是算法竞赛中非常经典的一种解题范式：**用严谨的数学推导把连续/复杂的解空间“缩小”为一个有限的小集合，然后对这个集合进行高效的暴力枚举！**

你看到的 `que = [0] * (4 * n)` 以及外层循环的写法，其实是**手写双端队列（Deque）**和**01-BFS 算法特性**的一个极致性能优化技巧。

这里有两个关键细节需要拆解：

---

### 一、 为什么 `que` 的大小要开到 `4 * n`？

在 01-BFS 中，我们使用的是**双端队列（Double-ended Queue）**：

* 边权为 **0** 的节点，需要插入到**队头**（`l -= 1`）；
* 边权为 **1** 的节点，需要插入到**队尾**（`r += 1`）。

如果用 Python 的普通 `list` 模拟队头插入（`list.insert(0, x)`），每次插入的时间复杂度是 $O(N)$，会让算法直接退化成 $O(N^2)$。

为了实现 **$O(1)$ 的队头和队尾插入**，代码使用了**双向扩展数组**技巧：

1. **初始化**：开辟一个大小为 `4 * n` 的静态数组。
2. **指针置中**：将队头 `l` 和队尾 `r` 的初始位置都放在中间 `2 * n` 处（`l = r = 2 * n`）。
3. **双向扩展**：
* 向队头插元素时 `l -= 1`（利用左边的空间）；
* 向队尾插元素时 `r += 1`（利用右边的空间）。



因为一个节点在一次 BFS 中最多被入队几次，左右两边各预留 `2 * n` 的空间能够**绝对保证数组不会向左或向右溢出**，从而以极高效率实现了手写 Deque！

---

### 二、 为什么不是“每次把一条边变成 0”，而是外层重新跑 BFS？

你提到的“每次把一条边变成 0”，实际上对应着断层点 $i$ 从 $0$ 增加到 $M-1$ 的过程：

* 当 $i = 0$ 时：所有边的权值都是 $1$；
* 当 $i = 1$ 时：第 $0$ 条边的权值变为了 $0$（免费）；
* 当 $i = 2$ 时：第 $1$ 条边的权值也变为了 $0$……

**为什么不能只“局部修改”而必须重新 BFS？**

1. **图的全局最短路发生了拓扑改变**：
当一条边的权值从 $1$ 变成 $0$ 时，不仅这条边本身的通行时间变短了，而且**全图中大量节点经过这条边的最短路径和松弛顺序都可能被破坏**。
2. **增量更新（Dynamic Shortest Path）极其复杂**：
只更新一条边的权值并维护全图最短路，在图论中属于“动态图最短路”。虽然理论上有增量算法，但写起来极其繁琐，常数巨大。
3. **重新跑 01-BFS 足够快**：
01-BFS 的时间复杂度只有线性 $O(N + M)$。既然断层点只有 $M$ 个，直接外层枚举 $i$，每次重置 `dis` 数组并用静态数组跑一次全新的 01-BFS，**代码极其简洁且常数小到极致**。

---

### 总结

* **`que = [0] * (4 * n)`**：是为了用静态数组在 $O(1)$ 时间内手写支持双向插入的 Deque，避免 Python 动态列表插入和内置 `collections.deque` 的巨大常数开销。
* **外层重新跑 BFS**：是因为每多一条 $0$ 权边，全图的最短路拓扑结构就会改变，重新跑一次线性的 $O(N+M)$ 01-BFS 是最稳妥、最快且不容易写错的做法。

对于这段总结，有两个非常微小的细节可以做最严谨的补充：

1. **是“静态双向预留数组”，而非真正的“环形队列”**：
代码中使用的是 `l = r = 2 * n` 初始化，利用大数组向左右两端线性延伸，这种写法叫 **双端预留静态数组 (Deque with Offset)**。它和取模的“环形队列 (Circular Queue)”效果完全一致，但**没有取模运算 `%**`，在 Python 这种解释型语言里常数更小、运行更快。
2. **`l -= 1` 抢占队头不是冗余，而是严格的 Dijkstra 贪心**：
当通过 0 权边松弛点 $v$ 时，将 $v$ 压入队头（`l -= 1`）并在下一轮立刻弹出 $v$，这本质上是 **Dijkstra 算法中对 0 权边的优先扩展**。虽然指针 $l$ 减小了，但由于有 `if dis[v] > nd` 的严格关卡，每个点只会被有效松弛有限次，因此这部分时间完全被包含在了线性的 $O(N + M)$ 复杂度之内。
