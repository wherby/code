## Re-labeling

是的，你的直觉非常敏锐！这里最核心、最惊艳的精髓**正是“在线重新编码（Online Re-encoding / Dynamic Rank Allocation）”**。

这种技巧在图论和大数比较中极其巧妙，它的本质是：**利用优先队列（Dijkstra）出队天然具备的“单调性”，在运行过程中动态地把“庞大且不可存的大数”实时压缩/重新编码为“小范围的等价整数（Rank）”**。

我们可以把这个“在线重新编码”的机制拆解为三个极其优雅的动作：

### 1. 状态降维与惰性压缩（Lazy Rank Allocation）

在标准的 Dijkstra 中，状态通常是 `(d[u], u)`。但这道题的 `d[u]` 是一个超长 base-$k$ 数，直接存会内存/时间爆掉。
代码没有尝试在入队时就计算出最终的真实排名，而是采取了“惰性编码”：

* 进队时，只用 **`(前驱的旧编码, 当前边权)`** 组合成临时 Key。
* 因为前驱的旧编码（`prev_dis`）已经保证了高位的相对大小，当前边权（`edge`）决定了低位，这两个值的组合就**精准代表了当前新状态的“相对字典序”**。

### 2. 借助 Heap 出队的“单调性”完成在线离散化

Dijkstra 的堆（`pq`）每次弹出的，必然是**当前全局未处理状态中“二元组字典序最小”的那一个**。
这意味着，所有被弹出的 `(prev_dis, edge)` 序列在时间轴上是**严格单调不减**的！

有了这个单调性，重新编码就变得极其简单且在线：

* **如果 `(prev_dis, edge)` 变大了**：说明我们遇到了一个全新的、严格更大的数值，于是 `cur_idx += 1`，分配一个新的编码。
* **如果 `(prev_dis, edge)` 和上一次完全一样**：说明两条不同路径凑出了完全相等的数值，赋予相同的 `cur_idx`（编码不变）。

这就是为什么代码里只需要极其简洁的几行就完成了离散化：

```python
if (prev_dis, edge) > (cur_prev_dis, cur_edge):
    cur_prev_dis = prev_dis
    cur_edge = edge
    cur_idx += 1  # 在线生成新的编码
dis_idx[u] = cur_idx  # 赋予节点 u 新的离散化编码

```

### 3. 编码回馈与状态传递（Feedback Loop）

一旦节点 $u$ 在出队时获得了它的最新重新编码 `dis_idx[u]`，这个全新的 `dis_idx[u]` 就会**立刻作为高位编码**，继续用于松弛 $u$ 的邻接点 $v$：

```python
heappush(pq, f(dis_idx[u], d, v)) # 用刚生成的新编码去构建子节点的状态

```

这就形成了一个“出队 $\to$ 分配新编码 $\to$ 用新编码压包扩展子节点 $\to$ 子节点入队”的完美闭环。

---

### 为什么这种“在线重新编码”如此高级？

1. **消除离线依赖**：普通的做法（如分层 BFS）必须先离线收集完一整层的所有转移，整体做一次 `sort` 离散化，再推导下一层。而这个做法**完全在线**，靠堆的优先级自然完成了“边出队边离散化”。
2. **空间极致压缩**：任何时刻，节点存储的编码 `dis_idx[u]` 最大都不会超过 $N$（节点总数）。把可能无限长的 base-$k$ 大数，在 Run-time 实时映射到了 $[0, N-1]$ 的整数空间内。
3. **前导 0 与等值路径的自适应**：如果走的是 0 权边，压入的组合依然是 `(0, 0)`，出队时与上一个 `(0, 0)` 比较相等，`cur_idx` 根本不会自增，直接完美处理了前导 0 和多条同权路径的情况。

这种“用 Dijkstra 的单调出队序代替离散化排序，在线实时分配小整数 ID” 的思想，在处理“超大状态比较”、“高精度路径字典序”类的高级图论题目中，确实是非常灵动且高级的技巧！

---

### 1. 为什么说它本质上就是“前缀数组的 Re-labeling”？

在 **后缀数组（Suffix Array）** 或 **后缀树/SAM** 的构建过程中，我们经常需要比较两个长度翻倍的前缀 $S[i \dots i+2^k-1]$ 和 $S[j \dots j+2^k-1]$。由于字符串太长无法直接比较，算法的做法是：

1. 用上一轮已经计算好的 **前半段 Rank**（代表高位）。
2. 用上一轮已经计算好的 **后半段 Rank**（代表低位）。
3. 将二元组 $\big(\text{Rank}(\text{Left}), \text{Rank}(\text{Right})\big)$ 进行离散化（排序/桶排序），**重新赋给它们一个新的 1D Rank**（即重编码）。

**而在本题的 BFS / Dijkstra 中，完全是同一种思想：**

* **前半段（高位前缀）**：由前驱节点 $u$ 的 **前缀编码 `dis_idx[u]**` 决定。
* **后半段（低位字符）**：由当前这条边的 **边权 $w$** 决定。
* **重编码（Renaming）**：将二元组 $\big(\text{dis\_idx}[u], w\big)$ 按照字典序进行离散化，赋予目标节点 $v$ 一个全新的 **前缀编码 `dis_idx[v]**`。

---

### 2. “前缀重编码”在两种框架下的统一

无论是**离线分层 BFS** 还是你写的**在线魔改 Dijkstra**，它们本质上都在维护一个 **前缀状态 Equivalence Class（等价类/Rank）**：

```
旧前缀编码 (Prefix Rank) + 新字符 (Edge Weight)  ===>  新前缀编码 (Next Prefix Rank)

```

| 维 度 | 离线分层 BFS 做法 | 在线魔改 Dijkstra 做法 |
| --- | --- | --- |
| **层级推进** | 显式按路径长度 $L = 0, 1, 2 \dots$ 分层 | 隐式由优先队列 (Heap) 维护的单调序推进 |
| **重编码时机** | 收集完第 $L$ 层的所有转移，**批量 `sort` 离散化** 赋新 Rank | 在堆弹出 `(dis_idx[u], w)` 时，**在线双指针增量赋新 Rank** |
| **前缀等价性** | 相同二元组在同层内获得相同的 `Rank` | 相同二元组连续出队，获得相同的 `Rank` |

---

### 3. 这个理解带来的深远启发

把你提到的这个“前缀数组重编码”视角延伸开来，这类思想在高级算法中到处可见：

1. **DAG / 图上的 Trie 树最小化（DFA Minimization）**：
Hopcroft 算法或 Myhill-Nerode 定理中，将状态按转移和输出不断划分为更细的等价类，本质也是对前缀/后缀进行重编码。
2. **倍增法求树上任意两点的字典序**：
树上倍增（LCA 思想）结合后缀数组重编码，可以在 $\mathcal{O}(\log N)$ 时间内比较树上任意两条路径所代表字符串的字典序大小。
3. **图上超大数的代数离散化**：
当我们无法直接表示“状态的值”（因为会呈指数级增长，如 $k^L$），但**状态值的相对大小关系只取决于 (前缀, 增量) 的组合**时，**“前缀重编码”就是将指数级状态空间打回线性空间 $\mathcal{O}(N)$ 的终极武器**。
