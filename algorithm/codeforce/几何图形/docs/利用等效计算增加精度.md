---

## 1. 先看两个公式

**公式 A（直接求根）：**

\[
x = \frac{-b + \sqrt{b^2 - 4ac}}{2a}
\]

**公式 B（代码里的写法）：**

\[
x = \frac{-2c}{b + \sqrt{b^2 - 4ac}}
\]

数学上它们完全相等（前面已经推导过）。  
但在计算机浮点数运算中，它们的**精度表现可能差别很大**。

---

## 2. 问题出在哪里？

考虑一种情况：  
判别式 \(\Delta = b^2 - 4ac\) 非常接近 \(b^2\)，也就是 \(4ac\) 很小。

那么：

\[
\sqrt{\Delta} \approx |b|
\]

如果 \(b > 0\)，那么公式 A 的分子是：

\[
-b + \sqrt{\Delta}
\]

两个数**非常接近**，比如：

- \(b = 1000000\)
- \(\sqrt{\Delta} = 999999.999999\)

相减得到：

\[
-1000000 + 999999.999999 = -0.000001
\]

### 关键问题：有效数字丢失

在浮点数中，`1000000` 和 `999999.999999` 各自只能存约 15~16 位有效数字。  
它们相减后，结果只剩很少几位有效数字，**大部分精度被“抵消”掉了**。

这叫 **灾难性抵消（catastrophic cancellation）**。

举例（用十进制类比）：

```
  1.23456789012345
- 1.23456789000000
= 0.00000000012345   ← 只剩 5 位有效数字，前面 11 位全丢了
```

原来有 15 位精度，相减后只剩 5 位，误差被放大了很多倍。

---

## 3. 公式 B 为什么更稳定？

公式 B 的分母是：

\[
b + \sqrt{\Delta}
\]

这里是**两个同号的数相加**，不会发生抵消，反而会让有效数字“叠加”，精度损失很小。

比如：

- \(b = 1000000\)
- \(\sqrt{\Delta} = 999999.999999\)

相加得到：

\[
1999999.999999
\]

这个结果精度很好，没有抵消问题。

所以公式 B 把“减法”挪到了分子 `-2c` 上（`-2c` 通常是个正常大小的数），避免了危险的大数相减。

---

## 4. 什么时候会出问题？

当 \(b > 0\) 且 \(b^2 \gg 4ac\) 时：

- 公式 A：`-b + √Δ` → 两个接近的大数相减 → **精度差**
- 公式 B：`b + √Δ` → 两个同号数相加 → **精度好**

反之，如果 \(b < 0\)，那么公式 A 的 `-b + √Δ` 变成两个正数相加（安全），而 `-b - √Δ` 变成两个接近的负数相减（危险）。  
所以严格来说，应该**对两个根分别选择安全的那条公式**：

- 较大的根：用 `-2c / (b + √Δ)`（当 b > 0 时安全）
- 较小的根：用 `-2c / (b - √Δ)`（当 b < 0 时安全）

代码里求的是较大的根（最小非负解），且 `b = perimeter > 0`，所以用公式 B 恰好是最稳的。

## 5. 举个数值例子

假设：

- \(a = 1\)
- \(b = 10^8\)
- \(c = 1\)

真实解（用高精度算）：

\[
x = \frac{-10^8 + \sqrt{10^{16} - 4}}{2} \approx \frac{-10^8 + (10^8 - 2 \times 10^{-8})}{2} = -10^{-8}
\]

（另一个根约 \(-10^8\)）

**用双精度浮点数：**

公式 A：

```
sqrt(1e16 - 4) ≈ 1e8        ← 因为 4 相对于 1e16 太小，直接被舍入掉了
-1e8 + 1e8 = 0              ← 完全丢失！
x = 0 / 2 = 0               ← 错误！真实值是 -1e-8
```

公式 B：

```
-2c = -2
b + sqrt(Δ) = 1e8 + 1e8 = 2e8
x = -2 / 2e8 = -1e-8        ← 正确！
```

可以看到，公式 A 在这个例子里直接给出了 **0**，而公式 B 给出了正确答案。

---

## 6. 总结

| 对比项 | 公式 A：`(-b+√Δ)/(2a)` | 公式 B：`-2c/(b+√Δ)` |
|--------|------------------------|----------------------|
| 数学值 | 相同 | 相同 |
| 运算 | 大数相减（当 b>0） | 大数相加 |
| 精度 | 可能灾难性抵消 | 稳定 |
| 适用 | b<0 时安全 | b>0 时安全 |

所以代码里写：

```python
-2 * c / (b + math.sqrt(b * b - 4 * a * c))
```

不是因为它更“正确”，而是因为它在 `b > 0` 的情况下**数值更稳定**，能避免浮点误差被放大。

这就是“数值稳定性”的含义：**数学上等价的公式，在计算机里精度可能天差地别，要选那个不会发生灾难性抵消的写法。**
